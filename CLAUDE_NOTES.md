# Project Notes

- `skills/writing-skills/render-graphs.js` currently fails under the root `"type": "module"` package setting because it uses CommonJS `require`. Graphviz `dot` is also not installed in this environment, so DOT diagram verification may need a script fix or a different local setup.
- For Git-installed Codex marketplaces where the plugin lives at the repository root, use a marketplace plugin source of `"source": "url"` with the repository URL and ref. A repo-cloned marketplace entry using `"source": "local", "path": "./"` can be registered by `codex plugin marketplace add` but then skipped in `/plugins`.
- Skills that resolve a trunk/base branch must **detect** it, never assume `main`. This user deliberately configures git to use `master` as the default branch for new repos. Detect with `git rev-parse --verify --quiet master` / `main` (use whichever exists; ask if both or neither), not by hardcoding `main` or trying it first. Applied in `external-code-review` (Step 2) and `finishing-a-development-branch` (Step 2) in v1.4.0.
- Skill-triggering tests (`tests/skill-triggering/run-test.sh`) shell out to a real `claude -p --plugin-dir <repo-root>`, which loads skills from the **working tree** — no plugin reload needed to test an in-progress skill. Each run can take minutes (300s timeout). The description frontmatter is what drives triggering, so editing a skill's *body* after a GREEN pass does not require re-running the trigger test.
- Skill prose should describe platform capabilities, not exact tool names, when the same concept exists across agent harnesses. Exact names such as `TodoWrite`, `update_plan`, `write_todos`, or `todowrite` belong in mapping/bootstrap docs as known examples; the core skill should tell the agent to discover the available runtime tool and fall back gracefully.
- Treat user-supplied reference docs for a task as session input, not repo documentation, unless the user explicitly asks to keep them. External CLI docs can stale quickly; implement against them, but do not commit local copies or README links to those copies by default.
- **Comparing against upstream Superpowers:** the fork point is upstream tag `v5.0.6` (commit `eafe962`, 2026-03-25) — it exists as a tag in the upstream repo, so `git diff v5.0.6..HEAD -- <path>` there separates upstream improvements from this fork's deliberate changes. Constraints any port must respect: branches not worktrees, controller-commits-only (via `commit-message` skill), resume-same-implementer for review fixes (upstream independently adopted the same rule in v6.0.0 — the divergence is validated, not a drift to fix), and the fork's own skills (external-review, using-stitch, …). Full port analysis: `docs/2026-07-10-superpowers-port-proposals.md` (deliberately uncommitted; regenerate by re-comparing if absent).
- **Independent review under Codex:** never invoke Codex as the external reviewer when the controller is Codex; use a different model family such as `claude -p`. A non-zero/empty-looking capture is not sufficient evidence of a failed review: preserve and inspect the reported output file, log, and session/transcript before retrying. Limit a document-review request to one session unless that evidence proves it produced no review.
- **Current Claude headless result shape:** with Claude Code 2.1.235, `claude -p --output-format json` can produce a transcript-style JSON array rather than one result object. The successful review run on 2026-08-19 ended with an item whose `type` was `result`; consumers must preserve native JSON and locate the terminal result rather than assuming top-level `.result`. That run also directly verified `--safe-mode`, `--permission-mode dontAsk`, and a preassigned `--session-id`.
- **Measure reviewer runtime at the process:** shell-tool wall time can include minutes spent waiting for user approval before the reviewer starts. Timeout and status reporting must use a start timestamp recorded by the managed reviewer process, not the duration reported for the surrounding tool call.
- **Review-attempt locks must examine the whole chain:** once `--after-terminal` creates more than one directory for a stable review key, returning the first glob match can hide a newer live attempt and permit a duplicate. Find every exact-key match, reject any live match, and validate retries against the unique chain tail.
- **Reviewer lifecycle paths and identities must be self-canonicalizing:** canonicalize the temp root before constructing or printing run paths, and have each detached supervisor record its own PID/start identity. Parent `$!` values and non-canonical `$TMPDIR` paths are not reliable across `setsid`, macOS `/var` symlinks, or later tool calls.
- **PowerShell `Start-Process -ArgumentList` does not quote path elements:** explicitly embed quotes around script and run-directory arguments, then test both the checkout and temp path with spaces under Windows PowerShell 5.1.
